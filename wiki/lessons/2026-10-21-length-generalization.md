# 덧셈 길이 일반화 실패

RSI(5단계)는 "조금 더 어려운 문제를 가끔은 맞힌다"에서 출발한다. 그런데 모델은 **학습한 길이보다 한 자리만 길어도 거의 0%** 였다.
모두 small(29.9M) 사전학습 모델에서 SFT 2,600 step 후 측정 ([SFT 페이지](../concepts/2026-10-21-sft.md)).

## 시도와 측정

| 시도 | 학습한 피연산자 길이 | 학습 범위 정확도 (greedy) | 바로 다음 길이 |
|---|---|---|---|
| 1. 기본 (답 정방향) | 1–3 (같은 길이끼리) | 1.00 / 1.00 / 0.99 | 4자리 greedy 0.0, pass@16 **0.000** |
| 2. 답을 거꾸로 (일의 자리부터) + 길이 섞기 | 1–3 (독립) | 1.00 / 1.00 / 0.98 | 4자리 pass@4 **0.001** |
| 3. 답 거꾸로 + 범위 확대 | 1–7 (독립) | 1–7자리 0.99–1.00 | 8+1 pass@16 0.002, 8+4 0.004, 8+8 **0.000** |
| 4. 16자리 고정 폭(0 채움) + 답 거꾸로 | 1–7 | 1–7자리 1.00 | 8자리 greedy **0.0**, pass@16 0.000 |
| 5. 4 + 절반은 숫자를 무작위 위치로 이동(shift) | 1–7 (연속 유효 자릿수) | 1–7자리 1.00 | **8자리 1.00**, 10자리 0.99, 12자리 0.88, 14자리 0.40, 16자리 0.065 |

## 무엇이 틀리는가

- 시도 1: `5258 + 5606` → `1085` (정답 10864). 앞자리는 비슷하게 맞고 **학습 때 본 최대 답 길이(4자리)에서 멈춘다.**
- 시도 2: `1354 + 0` → `541` (정답, 뒤집어서 4531). 더할 게 없는데도 틀린다 → **4자리 숫자를 읽지도 못한다.**
- 시도 3: `1234567 + 0` → `7654321` (맞음), `12345678 + 0` → `8754321` (6을 빠뜨림).
- 시도 4: `12345678 + 0` → `87654320000000000`. 거꾸로 쓴 8번째 자리(1)만 0. 학습 때 피연산자 8~16번째 자리는 **항상 0**이어서 "그 자리는 0"을 외웠다.
- 시도 5: `12345678 + 0` → `87654321000000000` (맞음), `99999999 + 1` → 맞음.

## 해석

- 답을 뒤집으면 받아올림 순서 문제는 풀린다. 하지만 모델이 "일의 자리가 어디 있는지"를 **위치(거리)로 찾는** 방식을 배웠고,
  RoPE에서 출력 자리와 필요한 피연산자 자리 사이의 거리는 숫자 길이에 따라 커진다. 본 적 없는 거리 → 엉뚱한 자리를 본다.
- 학습 범위를 1–3에서 1–7로 넓혀도 경계(7→8)에서 똑같이 무너졌다. 길이를 "늘려 가는" 규칙이 아니라 본 길이들을 각각 외운 셈이다.
- 처음에 "답 뒤집기는 알려진 해법"이라고 소개했지만, **이 모델·형식에서는 그것만으로 부족했다.** 근거 없이 논문 세부를 옮기지 않는다.

## 해결 (시도 4 + 5, 소유자 선택: 0으로 채워 길이 고정)

1. **고정 폭**: 모든 숫자를 16자리로 0을 채운다 → k번째 자리가 언제나 같은 위치 → 처음 보는 "거리"가 없다.
2. **자리마다 진짜 숫자를 보게 한다**: 절반의 문제는 숫자를 무작위 위치로 옮긴다(1354 → 1354000000). 연속 유효 자릿수는 여전히 7 이하라서
   "8자리 이상 연속된 숫자"는 처음 보는 난이도로 남는다.
3. 그러면 모델은 **자리마다 같은 규칙(두 숫자 + 받아올림)** 을 배우고, 긴 숫자에도 대부분 적용한다. 길수록 정확도가 떨어지는 부분(12~16자리)이
   RSI가 스스로 끌어올릴 대상이다.

교훈: 길이 일반화 실패는 "모델이 규칙 대신 위치별 패턴을 외웠다"는 신호다. 데이터가 모든 위치에서 같은 규칙을 보여 주면 규칙을 배운다.

## 처음에 검토한 다른 선택지

- 피연산자도 거꾸로 쓰기: 출력 i번째 자리와 피연산자 i번째 자리가 둘 다 "시작에서 i번째"가 된다.
- 0으로 채워 같은 길이 맞추기 (zero-padding).
- 자리 표시 토큰 (index hints): 각 숫자 앞에 자리 이름을 붙여 위치 대신 **내용으로** 찾게 한다.
- 위치 인코딩 변경 (예: 위치 정보 없음, NoPE) — 모델 구조 변경.
