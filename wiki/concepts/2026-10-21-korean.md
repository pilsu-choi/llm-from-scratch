# 한국어 확장 (Stage 7)

전체 계획은 [로드맵](../2026-10-21-roadmap.md), 토크나이저의 원리는 [BPE 토크나이저](2026-10-21-bpe-tokenizer.md), 사전학습 루프와 bits/byte는 [사전학습](2026-10-21-pretraining.md) 페이지에 있다. 이 페이지는 `tokenizer.py`의 `extend`, `model.py`의 `load_checkpoint`(새 임베딩 행), `data.py`의 shard 섞기, `train.py`의 shard별 val을 설명한다.

## 1. 문제: 영어 토크나이저로 한국어를 읽으면

3단계 토크나이저는 영어 TinyStories로 병합 8192개를 배웠다 (`tok_chat`, 대화 특수 토큰 포함 vocab 8194). 한국어 문장을 넣으면 병합이 하나도 맞지 않는다. 한글 한 글자는 UTF-8로 3바이트이고, 그 3바이트가 **각각 토큰 하나**가 된다.

| 텍스트 | tok_chat bytes/token | 뜻 |
|---|---|---|
| 영어 TinyStories | 4.10 | 토큰 하나 ≈ 영어 4글자 |
| 한국어 TinyStories | **1.01** | 토큰 하나 ≈ 1바이트 = 한글 1/3글자 |

문맥 길이가 512토큰이니, 영어로는 약 2KB(이야기 하나)를 보는데 한국어로는 512바이트 ≈ **한글 170자**만 본다. 같은 연산으로 배우는 한국어 텍스트도 4배 적다. 바이트 토큰 3개를 이어 붙여야 한 글자가 되므로, 모델이 깨진 글자(�)를 만들 수도 있다.

## 2. 데이터

[g0ster/TinyStories-Korean](https://huggingface.co/datasets/g0ster/TinyStories-Korean) (MIT). 영어 TinyStoriesV2를 EEVE 모델로 **기계 번역**한 것이다. train 3.1GB, valid 31MB이고, valid는 영어 TinyStoriesV2 valid의 번역이라 두 val 세트가 같은 이야기를 담는다. 선택 이유는 [결정 기록](../decisions/2026-10-21-korean-data.md)에 있다. `scripts/get_data.sh ko`로 받는다.

번역체라서 문장이 영어 어순을 따르는 경우가 있고, 이름은 "팀", "릴리"처럼 음역된다. 이 단계의 목표(토크나이저와 이어서 학습하기의 원리)에는 충분하다.

## 3. 토크나이저 확장

처음부터 다시 배우면(영어 + 한국어로 새 BPE) 모든 토큰 id의 의미가 바뀐다. 그러면 지금까지 학습한 모델 가중치를 버려야 한다. 대신 **기존 병합 위에 새 병합을 덧붙였다** (`Tokenizer.extend`).

1. 한국어 텍스트를 지금 토크나이저로 인코딩한 상태에서 시작한다. 한국어 단어는 대개 바이트 토큰의 나열이다.
2. 거기서 가장 흔한 쌍을 찾아 합치는 BPE를 그대로 계속한다. 새 토큰 id는 **현재 vocab 다음 번호**(8194부터)를 받는다.
3. 기존 병합은 순서와 id가 그대로다. 그래서 **영어 인코딩이 바뀌지 않는다**. 측정한 영어 검증 문장의 인코딩이 확장 전과 완전히 같았다.

`Tokenizer.train`도 이제 빈 토크나이저(바이트 256개)를 `extend`하는 것으로 구현된다. 처음부터 배우기와 확장하기가 같은 함수다.

```bash
python -m scratchlm.tokenizer data/TinyStories-Korean-train.txt data/tok_ko.json \
  --extend data/tok_chat.json --vocab 8192 --max-mb 30   # 앞 30MB로 병합 8192개 추가 -> vocab 16386
```

| 토크나이저 | vocab | 한국어 bytes/token | 영어 bytes/token |
|---|---|---|---|
| tok_chat (3단계) | 8,194 | 1.01 | 4.10 |
| **tok_ko** (확장) | 16,386 | **6.53** | 4.10 (인코딩 동일) |

한국어 shard 전체(train 2,717,399개 문서)에서는 6.50 bytes/token = 469,970,129토큰이었다. 예: "옛날 | 옛날 | , | 따뜻하고 | 햇볕이 | ..." 처럼 **어절 하나가 토큰 하나**가 되는 경우가 많다. 한글 한 글자가 3바이트이니 토큰 하나 ≈ 2.2글자다. 한국어가 영어보다 bytes/token이 높게 나온 것은 바이트 수로 재기 때문이다 (글자당 3바이트).

## 4. 임베딩 이식 (vocab surgery)

모델 쪽에는 새 토큰 8192개의 임베딩 행(입력 `embed`, 출력 `head`)이 없다. `load_checkpoint(path, vocab_size=16386)`가 행을 덧붙인다.

- 새 행 = **기존 행들의 평균 + 작은 잡음**(표준편차 0.02). 무작위 초기화는 출력 로짓을 크게 흔들 수 있다. 평균 행은 "아무 토큰도 아닌 평균적인 토큰"이라서 학습 시작 시 모델이 덜 놀란다.
- 기존 행은 그대로라서, 영어 문장에 대한 모델 출력은 새 토큰에 확률을 조금 나눠 주는 것 말고는 변하지 않는다.
- 파라미터: 29.9M → 34.1M (8192행 x 256차원 x 2 = 4.2M 증가).

## 5. 이어서 사전학습 (continued pretraining)

3단계 모델(`runs/small`, 영어 16,000스텝, val 1.1638)에서 출발해 5000스텝 더 학습했다. 설정은 배치 64 x 512토큰, lr 5e-4 (3단계 1e-3의 절반), 워밍업 200, 코사인이다.

- **섞기**: `--train data/ko_train.bin,data/ts_train.bin`처럼 shard를 쉼표로 주면, 배치의 j번째 창은 j % 2번째 shard에서 뽑는다 (`data.batches`). **배치마다 한국어 절반, 영어 절반**이다. 영어를 계속 보여 주는 것은 10.3절(VLM)의 텍스트 복습과 같은 이유, 즉 잊어버림 방지다.
- **shard별 val**: `--val`도 쉼표로 여러 개를 주면 각각의 loss를 `vals`에 기록한다. 한국어 실력과 영어 보존을 따로 본다.
- **대조군 `ko_byte`**: 토크나이저를 확장하지 않고 `tok_chat` 그대로(한국어 = 바이트) 같은 설정으로 학습했다. 한국어 shard는 같은 train 파일의 앞 400MB(349,618개 문서)를 인코딩했다. 5000스텝 x 16,384 한국어 토큰 = 8,200만 토큰이라 이 크기로 충분하다.

### 다른 토크나이저끼리 비교하기: bits/byte

loss는 **토큰당** 정보량(nats)이다. 토큰 하나가 6.5바이트인 모델과 1바이트인 모델의 loss를 바로 비교하면 안 된다. 같은 텍스트를 바이트 기준으로 환산한다.

```
bits/byte = loss / ln 2 / (bytes/token)
```

두 val 세트는 같은 27,438개 한국어 문서다 (`ko_val.bin` 6.51, `ko_val_byte.bin` 1.00 bytes/token).

## 6. 결과

**한국어 val (bits/byte, 낮을수록 좋음)**

| 스텝 | ko_ext (tok_ko) | ko_byte (tok_chat) |
|---|---|---|
| 0 (학습 전) | 2.236 | 14.131 |
| 1000 | 0.606 | 0.898 |
| 2000 | 0.549 | 0.810 |
| 3000 | 0.521 | 0.761 |
| 4000 | 0.504 | 0.729 |
| 5000 | **0.497** | 0.714 |

(loss: ko_ext 10.0907 → 2.2407, ko_byte 9.7951 → 0.4949. 각 20배치 x 64창, 시드 고정.)

**영어 val (ts_val, 4.10 bytes/token)**: 출발 1.1638 (0.410 bits/byte) → ko_ext 1.2061 (0.424), ko_byte 1.1895 (0.419).

**속도**: ko_ext 35,476 tok/s, ko_byte 30,467 tok/s (5000스텝 시점. 다른 실행들과 GPU를 나눠 쓴 값이라 절대 속도보다 비율만 본다).

- **확장이 같은 연산으로 30% 더 좋다** (0.497 대 0.714 bits/byte). 같은 5000스텝에서 ko_ext는 한국어 약 533MB를, ko_byte는 82MB를 봤다. 토큰 하나에 6.5배 많은 텍스트가 들어 있기 때문이다. **같은 텍스트 양으로 비교해도** ko_ext가 앞선다: 1000스텝(약 107MB)에 이미 0.606으로, ko_byte의 5000스텝(82MB) 0.714보다 낮다.
- **학습 전 14.1 bits/byte**: 바이트당 8비트(256개 균등)보다도 나쁘다. 영어만 본 모델은 한글 바이트(0xEA~0xED 등)에 거의 0의 확률을 주므로, 균등 분포보다 더 크게 틀린다. 확장 쪽 2.24는 새 토큰이 평균 행에서 출발해 균등에 가깝게 퍼진 상태다 (loss 10.09 ≈ ln 16386 = 9.70보다 약간 높음).
- **영어는 거의 지켰다.** 한국어를 절반 섞은 5000스텝 후 영어 val이 3.6%(ext), 2.2%(byte) 올랐다. ext 쪽이 더 오른 이유는 출력 softmax가 16,386개로 넓어져 새 한국어 토큰에 확률이 새기 때문으로 보인다 (추정, 따로 재지 않음).
- **샘플** ("옛날 옛날,"로 시작, 온도 0.8, top-k 50, 약 400바이트로 길이를 맞춤):
  - ko_ext: "옛날 옛날, 한 마리의 작은 돼지가 있었어요. 돼지는 많은 다른 동물들이 있는 농장에서 살았지요. 그 돼지는 매우 배가 고팠어요. 먹을 것을 찾아 여기저기 다녔답니다. 어느 날, 돼지는 큰 잎사귀를 발견했어요. ..."
  - ko_byte: "옛날 옛날, 큰 바람이 불어서 치즈를 날려버렸답니다. 그들은 함께 재미있게 놀며 재미있게 보냈어요. 잠시 후, 그들은 자신들의 작업에 칠합을 묻었어요. ..."
  - 둘 다 문법은 대체로 맞는다. ko_ext는 이야기 흐름(인물 → 문제 → 사건)이 더 자주 이어지고, ko_byte는 첫 문장부터 인물 없이 "그들"이 나오는 식으로 흐름이 끊기는 경우가 있었다 (3개씩 본 인상이며 측정이 아님). 학습 중 로그의 ko_ext 샘플 하나에서는 "걸어서 걸어서 ..." 반복이 나왔다. 작은 모델의 흔한 실패다.
  - 학습 중 로그의 샘플은 120토큰이다. ko_byte는 120바이트 ≈ 40글자에서 끊겨 비교가 안 되므로, 위 샘플은 바이트 수를 맞춰 다시 뽑았다.

## 7. 정리

- 토크나이저는 **모델이 한 번에 보는 텍스트 양**을 정한다. 같은 모델, 같은 연산에서 한국어 bytes/token 1.0 → 6.5가 bits/byte 30% 차이로 나타났다.
- 확장은 기존 id를 지키므로 학습한 가중치를 버리지 않는다. 새 행만 덧붙이면 된다.
- 토크나이저가 다른 모델은 loss가 아니라 bits/byte로 비교한다.
- 새 언어를 배울 때 옛 언어를 섞어 주면 잊어버림이 작다 (영어 val +2~4%).

## 9. 실습

1. **섞는 비율**: 한국어 : 영어를 3:1, 1:3으로 바꿔 보자 (`--train`에 같은 shard를 여러 번 쓰면 비율이 바뀐다). 한국어 bits/byte와 영어 보존이 어떻게 맞바뀌는가?
2. **병합 수**: 8192 대신 2048, 16384개를 확장하면 bytes/token과 bits/byte는? 임베딩 행이 늘어나는 비용과 비교하라.
3. **새 행 초기화**: 평균 대신 무작위(N(0, 0.02))로 두면 학습 초반(1000스텝) loss가 어떻게 다른가?
4. **한국어 SFT와 RSI**: 덧셈 대화를 한국어로("3과 5를 더하면?") 만들어 4~5단계를 한국어로 다시 돌릴 수 있는가? 숫자 토큰은 그대로이므로 덧셈 실력이 옮겨 가는가?

## 10. 실행

```bash
scripts/get_data.sh ko                                     # 한국어 TinyStories 받기
scripts/pgx.sh python -m scratchlm.tokenizer data/TinyStories-Korean-train.txt data/tok_ko.json \
  --extend data/tok_chat.json --vocab 8192 --max-mb 30
scripts/pgx.sh python -m scratchlm.data data/TinyStories-Korean-train.txt data/tok_ko.json data/ko_train.bin
scripts/pgx.sh python -m scratchlm.data data/TinyStories-Korean-valid.txt data/tok_ko.json data/ko_val.bin
DETACH=ko_ext scripts/pgx.sh python -m scratchlm.train --name ko_ext --tok data/tok_ko.json --init runs/small/ckpt.pt \
  --train data/ko_train.bin,data/ts_train.bin --val data/ko_val.bin,data/ts_val.bin \
  --steps 5000 --lr 5e-4 --warmup 200 --eval_every 1000 --prompts "Once upon a time|옛날 옛날,"
```
