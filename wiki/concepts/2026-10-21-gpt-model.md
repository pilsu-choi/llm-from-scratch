# Decoder-only GPT

전체 학습 계획은 [로드맵](../2026-10-21-roadmap.md), 입력 쪽은 [BPE 토크나이저](2026-10-21-bpe-tokenizer.md), 기울기 계산의 원리는 [numpy autograd](2026-10-21-numpy-autograd.md) 참고. 이 페이지는 `scratchlm/model.py`를 원리 중심으로 설명한다.

## 1. 전체 구조

```
ids (B,T)
 -> Embedding            (B,T,d)
 -> N x Block            x = x + Attn(RMSNorm(x));  x = x + SwiGLU(RMSNorm(x))
 -> RMSNorm              (B,T,d)
 -> @ E^T  (tied)        logits (B,T,V)
 -> cross_entropy(logits, next-token targets)
```

**next-token prediction**: 위치 `t`의 출력이 `ids[t+1]`을 맞히도록 학습한다 (`m(ids[:, :-1], ids[:, 1:])`). 한 시퀀스에서 T개의 학습 신호가 동시에 나오므로 데이터 효율이 좋고, 라벨이 텍스트 자체라 사람의 주석이 필요 없다.

**decoder-only인 이유**: 위치 `t`는 `<= t`만 볼 수 있어야 "다음 토큰 예측"이 정직한 문제가 된다 (미래를 보면 정답을 베낀다). 이 제약이 causal mask이고, 같은 구조가 학습(병렬)과 생성(한 토큰씩)에 그대로 쓰인다. encoder나 cross-attention이 필요 없어 블록 하나를 N번 쌓으면 끝이다.

**1.5단계 MLP LM과의 차이** (autograd 페이지의 데모):

| | MLP LM | GPT |
|---|---|---|
| 문맥 | 고정 8 byte | 최대 `ctx_len`=512 토큰 |
| 위치 처리 | `W1`의 8개 블록(위치별 고정 가중치) | RoPE (상대 위치) |
| 문맥 참조 | 이어붙여 선형 변환 (내용 무관) | attention: 내용 기반으로 가중 평균 |
| 파라미터 | 121,344 | 29.9M (small) |

attention은 "어느 과거 위치를 얼마나 볼지"를 입력 내용(`q·k`)으로 정하므로, 8 byte 밖의 주어나 앞 문장도 가져올 수 있다.

## 2. 손으로 만든 레이어

```python
class Linear:     y = x @ W.T            # W: (d_out, d_in), bias 없음
class Embedding:  y = W[ids]             # 행 lookup, W: (V, d)
```

- `Linear`는 `W`를 `(d_out, d_in)`로 저장해 `x @ Wᵀ`를 계산한다. 행렬곱의 backward(`g @ W`, `xᵀ @ g`)는 autograd 페이지에서 유도한 그대로다.
- `Embedding.forward`는 `weight[ids]`다. backward는 선택된 행에 기울기를 흩뿌려 더한다 (같은 토큰이 여러 번 나오면 누적, autograd 페이지의 `np.add.at`와 같은 원리).
- bias가 없는 이유: 뒤따르는 RMSNorm이 스케일을 맞춰 주고, 상수 이동은 거의 이득이 없으면서 파라미터와 코드만 늘린다.

**의존성 정책**: torch에서는 **텐서 연산, autograd, `nn.Module`, `nn.Parameter`**만 가져온다. `nn.Linear`, `nn.Embedding`, `torch.optim`은 쓰지 않는다. 레이어의 수식을 직접 쓰는 것이 학습 목적이고, 옵티마이저(AdamW)는 3단계에서 직접 만든다 (`test_overfits_one_sequence`도 `p -= 0.5 * p.grad`의 평범한 SGD를 쓴다). 반대로 `nn.Module`과 `Parameter`는 파라미터 등록, `.to(device)`, `parameters()` 같은 부기 작업만 하므로 허용한다.

## 3. RMSNorm과 pre-norm

```
LayerNorm(x) = (x - mean(x)) / sqrt(var(x) + eps) * g + b
RMSNorm(x)   =  x / sqrt(mean(x²) + eps) * g          (코드: eps=1e-6)
```

RMSNorm은 평균 빼기와 bias를 버렸다. 정규화의 핵심 효과는 **스케일 고정**(활성값 크기를 일정하게)이고, 평균 제거는 그 효과에 거의 기여하지 않는다는 관찰에 근거한다. 연산이 줄고 파라미터가 `2d`에서 `d`로 준다. 코드는 `x.float()`로 올려 fp32에서 `x²`의 평균과 `rsqrt`를 계산한 뒤 `type_as(x)`로 되돌린다. bf16은 가수부가 7비트라 제곱합을 누적하면 오차가 커지기 때문이다. `test_rmsnorm_and_cross_entropy_match_torch`가 `F.rms_norm`과 일치함을 확인한다.

dtype 세부: bf16 autocast 아래에서도 정규화 결과(`type_as(x)`)에 fp32 `weight`를 곱하므로 타입 승격으로 **출력은 fp32**다. 임베딩(fp32 파라미터)부터 시작하는 잔차 스트림도 fp32로 유지되고, autocast는 matmul(Linear, attention)에서만 bf16으로 내린다. 즉 "activation 전부 bf16"이 아니다.

**pre-norm vs post-norm**:

```
post-norm:  x_{l+1} = Norm(x_l + f(x_l))
pre-norm :  x_{l+1} = x_l + f(Norm(x_l))      <- 이 코드
```

pre-norm의 잔차 경로는 정규화를 거치지 않는 **항등 경로**다. 기울기가 `∂x_{l+1}/∂x_l = I + ∂f(Norm(x_l))/∂x_l`이라 `I` 항이 맨 위층 loss에서 맨 아래층까지 곧장 전달된다 (autograd 페이지의 "여러 경로의 합"). post-norm은 매 층마다 기울기가 Norm의 야코비안을 통과하므로 깊을수록 불안정해 warmup에 민감하다. 마지막 출력 전에는 `self.norm`을 한 번 더 둔다 (잔차 스트림이 정규화되지 않은 채 쌓였기 때문).

## 4. Attention

```python
q, k, v = self.qkv(x).view(B, T, 3, H, hd).permute(2, 0, 3, 1, 4)   # 각 (B, H, T, hd)
```

shape 흐름 (small: B=16, T=512, d=512, H=8, hd=64):

```
x            (B, T, d)
qkv(x)       (B, T, 3d)  -> view (B, T, 3, H, hd) -> permute (3, B, H, T, hd)
q, k, v      (B, H, T, hd)
q @ kᵀ       (B, H, T, S)       S = 키 길이 (캐시가 없으면 T)
softmax @ v  (B, H, T, hd) -> transpose(1,2) (B, T, H, hd) -> reshape (B, T, d) -> proj
```

head를 나누는 것은 서로 다른 "관계 유형"(이전 토큰, 구문 짝 등)을 독립적으로 배우게 하기 위해서다. 총 비용은 head 수와 무관하다 (`H·hd = d`).

**scaled dot product**: `softmax(q kᵀ / sqrt(hd)) v`. `q`, `k`의 성분이 분산 1이면 `q·k`는 `hd`개 항의 합이라 분산이 `hd`가 된다. `sqrt(hd)`로 나누어 분산을 1로 되돌리지 않으면 softmax 입력이 커져 거의 one-hot으로 포화되고 기울기가 사라진다.

**causal mask**: `mask = ones(T, S).tril(S - T)`. `tril(k)`는 `col <= row + k`인 칸을 남긴다. KV cache를 쓰면 쿼리는 전체의 **마지막 T개 위치**이므로 쿼리 `t`의 실제 위치는 `S - T + t`이고, 그보다 오른쪽 키만 가리면 된다. 예: 캐시 2개 + 새 토큰 3개 (T=3, S=5, `tril(2)`):

| 쿼리 (실제 위치) | k0 | k1 | k2 | k3 | k4 |
|---|---|---|---|---|---|
| q0 (2) | 1 | 1 | 1 | 0 | 0 |
| q1 (3) | 1 | 1 | 1 | 1 | 0 |
| q2 (4) | 1 | 1 | 1 | 1 | 1 |

디코딩 한 토큰(T=1)이면 `tril(S-1)`로 한 행이 전부 1이고, 캐시가 없으면(T=S) 보통의 하삼각이다.

**수동 vs SDPA**: 수동 경로는 `softmax(masked_fill(q kᵀ/sqrt(hd), -inf)) @ v`로 `(B,H,T,S)` 행렬을 메모리에 **만든다**. `F.scaled_dot_product_attention`은 같은 수식(기본 스케일이 `1/sqrt(hd)`)을 fused/flash kernel로 타일 단위로 계산해 T×S 행렬을 만들지 않는다. 그래서 결과는 같고(`test_manual_attention_matches_sdpa`, 1e-5) 메모리와 속도만 다르다 (11절). `is_causal=True`는 마스크를 **좌상단 정렬**의 하삼각으로 가정하므로 `T == S`일 때만 맞다. `T != S`(캐시 사용)에서는 쿼리가 오른쪽 아래 구간이므로 명시적 `attn_mask`를 넘긴다.

## 5. RoPE

위치를 임베딩에 더하는 대신 `q`, `k`를 위치에 따라 **회전**시킨다. head 차원을 앞뒤 반으로 나눠 `(x1_i, x2_i)`를 한 쌍으로 보고 (half-split 레이아웃, `x.chunk(2, -1)`), 쌍 `i`를 각도 `pos · θ^(-2i/hd)` (θ=10000)만큼 회전한다.

```
[x1']   [cos a  -sin a] [x1]        a = pos * θ^(-2i/hd),  i = 0 .. hd/2-1
[x2'] = [sin a   cos a] [x2]
```

`rope_tables`가 `cos`, `sin`을 `(ctx_len, hd/2)`로 미리 만들고, `apply_rope`는 `x1·cos - x2·sin`, `x1·sin + x2·cos`를 이어붙인다. i가 작을수록 빠르게(고주파), 클수록 느리게 회전해 여러 스케일의 거리를 구분한다. 회전은 fp32로 계산한다 (`x.float()`): bf16에서는 큰 `pos`의 각도 오차가 직접 위치 오차가 된다.

**왜 상대 위치만 남는가** (증명 스케치): 쌍 하나를 2차원 벡터로 보면 위치 `m`의 쿼리는 `R(m) q`, 위치 `n`의 키는 `R(n) k`다. `R(a)`는 각도 `a`의 회전 행렬이므로 `R(a)ᵀ = R(-a)`, `R(a)R(b) = R(a+b)`이고

```
(R(m) q)ᵀ (R(n) k) = qᵀ R(m)ᵀ R(n) k = qᵀ R(n - m) k
```

`m`, `n`이 아니라 **차이 `n-m`에만** 의존한다. 모든 쌍의 합인 전체 내적도 마찬가지다. 또 회전은 길이를 보존하므로 `‖R q‖ = ‖q‖`다. `test_rope_depends_only_on_relative_position`이 두 성질을 모두 확인한다: `dot(3, 10) == dot(40, 47)` (차이 7로 같음), `norm(rope(q)) == norm(q)`.

학습된 절대 위치 임베딩과 달리 추가 파라미터가 없고, 위치 정보가 attention 점수 안에서 직접 상대 거리로 작동한다. `v`는 회전하지 않는다 (위치는 "누굴 볼지"를 정하는 점수에만 필요하다).

## 6. SwiGLU

```
SwiGLU(x) = down( silu(gate x) ⊙ (up x) ),    silu(g) = g · sigmoid(g)
```

코드는 `g * torch.sigmoid(g) * up(x)`다. `silu(gate x)`가 `up x`의 각 성분을 부드럽게 열고 닫는 학습된 게이트 역할을 한다 (GELU MLP는 `down(gelu(up x))`로 게이트가 없다).

행렬이 3개(gate, up, down)이므로 같은 파라미터 예산을 맞추려면 `d_ff`를 줄여야 한다. 4d GELU MLP는 `2 · d · 4d = 8d²`, SwiGLU는 `3 · d · d_ff`이므로 `d_ff = 8d/3`. 코드는 이를 **64의 배수로 올림**한다 (GPU 타일 정렬):

```
d_ff = 64 * ceil(8d / 3 / 64)
d=512: 8·512/3 = 1365.33 -> /64 = 21.33 -> ceil 22 -> 22·64 = 1408
d=768: 8·768/3 = 2048    -> /64 = 32    -> 32·64 = 2048
```

## 7. 초기화

- 모든 `Linear`, `Embedding`: `N(0, 0.02²)`. RMSNorm의 `g`는 1.
- **잔차 쓰기 projection** (`attn.proj`, `mlp.down`)만 `std = 0.02 / sqrt(2 · n_layer)`. GPT-2의 방식이다. 잔차 스트림은 층마다 두 번(attn, mlp) 무엇인가를 **더하므로**, 독립적이라면 분산이 `2L`배로 자란다. 각 기여의 표준편차를 `1/sqrt(2L)`로 줄이면 깊이와 무관하게 스트림의 크기가 대략 일정하게 유지된다.
- **tied embeddings** (`tie_embeddings=True`): 로짓을 `norm(x) @ E.weight.T`로 계산해 입력 임베딩과 출력 행렬을 공유한다. `V·d` 파라미터가 절약되고 (small에서 4.2M, 전체의 14%), 토큰의 "입력 의미"와 "출력 의미"가 같은 벡터 공간을 쓰게 된다.

**초기 loss 점검**: 초기 모델은 거의 균등 분포를 내야 하므로 loss ≈ `ln V`다. V=8192면 `ln 8192 = 13 ln 2 = 9.011`. 측정은 9.114로 약간 높은데, 로짓 분산이 `d · 0.02² = 0.205` (표준편차 약 0.45)이고 로짓 분산이 `σ²`이면 loss가 대략 `σ²/2 ≈ 0.10` 오르기 때문이다 (대략적 추정이며 측정값 +0.103과 맞는다). `ln V`에서 크게 벗어나면 초기화나 마스크 버그의 신호다. `test_initial_loss_is_near_uniform`은 V=97에서 `ln 97`과 0.1 이내인지 확인한다.

## 8. 파라미터 수 공식

```
N = V·d (+ V·d 이면 untied)  +  L · (4d² + 3·d·d_ff + 2d)  +  d
         embedding               qkv+proj  gate/up/down  두 norm    최종 norm
```

`qkv`가 `3d²`, `proj`가 `d²`이므로 attention은 `4d²`다. (`test_param_count_formula`가 tie 여부 둘 다 검증한다.)

**small** (V=8192, d=512, L=8, H=8, d_ff=1408):

```
embedding   8192·512                    =  4,194,304
layer       4·512² = 1,048,576
            3·512·1408 = 2,162,688
            2·512 = 1,024               =  3,212,288
L=8 layers  8 · 3,212,288               = 25,698,304
final norm                              =        512
total                                   = 29,893,120  ≈ 29.9M
```

**base** (d=768, L=12, H=12, d_ff=2048):

```
embedding   8192·768                    =  6,291,456
layer       4·768² = 2,359,296
            3·768·2048 = 4,718,592
            2·768 = 1,536               =  7,079,424
L=12 layers 12 · 7,079,424              = 84,953,088
final norm                              =        768
total                                   = 91,245,312  ≈ 91.2M
```

untied로 바꾸면 small은 `+4,194,304`로 약 34.1M이다 (실습 3).

## 9. cross_entropy

```
loss = mean over {t : target_t >= 0} of  ( logsumexp(z_t) - z_t[target_t] )
```

이는 `-log softmax(z)[target]`과 같다 (autograd 페이지 5절). `logsumexp`가 내부에서 max를 빼므로 수치적으로 안정하다. 코드는 `logits.float()`로 fp32에 올려 계산한다: V=8192개 로짓의 지수 합을 bf16으로 하면 손실이 부정확해지기 때문이다. `target == -1`은 `keep` 마스크로 합과 평균에서 제외한다 (평균의 분모도 `keep.sum()`). 4단계 SFT에서 프롬프트 부분을 `-1`로 두면 답변 토큰에 대해서만 loss가 계산된다. `gather` 인덱스는 `clamp(min=0)`으로 음수를 피한다. `F.cross_entropy(..., ignore_index=-1)`과 일치함을 테스트가 확인한다.

## 10. KV cache와 generate

캐시 없이 생성하면 매 토큰마다 길이 S 전체를 다시 계산한다. 그런데 과거 위치의 `k`, `v`는 (causal이므로) 새 토큰이 와도 **변하지 않는다**. 그래서 층마다 `k`, `v`를 저장해 두고 새 토큰의 `q`, `k`, `v`만 계산한다.

- **prefill**: 프롬프트 전체를 한 번에 통과시키며 캐시를 채운다 (`caches = [{} for _ in blocks]`).
- **decode**: 토큰 1개(T=1)만 넣고 `cat([cache, new])`로 키를 늘린다. 비용은 한 단계에 `q kᵀ`가 `1×S`이므로 **O(S)**. 캐시가 없으면 한 단계에 T=S 전체의 `O(S²)`를 다시 계산한다.
- **캐시 메모리**: 시퀀스당 `2 · L · S · d` 원소 (k와 v, 층 L개, 길이 S, 폭 d). small, S=512면 `2·8·512·512 = 4.2M` 원소.
- **RoPE 위치 오프셋**: `GPT.forward`가 `pos = 캐시된 길이`로 `cos[pos:pos+T]`를 잘라 쓴다. 캐시된 `k`는 이미 자기 위치로 회전된 상태로 저장되므로, 새 토큰은 이어지는 위치의 각도를 받아야 한다. `test_kv_cache_matches_full_forward`는 7토큰 prefill 후 한 토큰씩 넣은 결과가 전체 forward와 일치함을 확인한다.

**샘플링**: `temperature == 0`이면 `argmax` (greedy). 아니면 `logits / temperature`를 softmax한 분포에서 `multinomial`로 뽑는다. 온도가 낮으면 분포가 뾰족해지고 높으면 평평해진다. `top_k`가 있으면 상위 k개 밖의 로짓을 `-inf`로 만들어 꼬리 확률을 잘라낸다. 길이가 `ctx_len`에 도달하면 멈춘다.

## 11. 측정 (PGX GB10, small, B=16, T=512, fwd+bwd 10 step)

`python -m scratchlm.model`의 출력 (3 step warmup 후 10 step):

| attention | dtype | 처리량 | peak 메모리 |
|---|---|---|---|
| manual | fp32 | 21.9k tok/s | 5.4 GiB |
| manual | bf16 | 32.3k tok/s | 4.9 GiB |
| SDPA | fp32 | 33.0k tok/s | 4.7 GiB |
| SDPA | bf16 | 56.3k tok/s | 3.6 GiB |

주의 (TF32): NGC 컨테이너는 `TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=1`로 fp32 matmul을 TF32(가수부 10비트)로 강제한다.
처음 측정한 fp32 행(manual 26.7k, SDPA 41.9k)은 실제로는 TF32였다. `scripts/pgx.sh`에서 이 변수를 0으로 꺼서 위 표는 진짜 fp32다.

초기 loss 9.114 (`ln 8192 = 9.011`, 7절).

해석:

- SDPA는 T×S 행렬을 만들지 않아 메모리가 줄고(fp32 5.4 -> 4.7 GiB) 메모리 이동이 줄어 빠르다. bf16은 matmul이 빨라지고 activation이 반으로 준다. 둘의 효과가 겹쳐 SDPA+bf16이 manual+fp32의 약 2.6배(56.3 / 21.9)다.
- **FLOPs/token** ≈ `6N` (forward 2N + backward 4N) + attention 항 `12 · L · T · d` (T×S 행렬곱은 파라미터에 없는 비용):

```
6 · 29.9M            ≈ 0.179 GFLOP
12 · 8 · 512 · 512   = 25.2M ≈ 0.025 GFLOP
합                   ≈ 0.204 GFLOP/token
0.204 GFLOP · 56.3k tok/s ≈ 11.5 TFLOPS
```

이전에 측정한 GB10의 bf16 matmul 약 68 TFLOPS의 **약 17%**다. 작은 모델이라 행렬이 작고 kernel launch와 elementwise 연산(RMSNorm, RoPE, SiLU)의 비중이 커서 matmul 피크에 못 미친다. `torch.compile`로 연산을 fuse하는 것이 3단계의 개선 수단이다.
- **대략의 사전학습 시간**: 500M 토큰 / 56.3k tok/s ≈ 8,900초 ≈ **2.5시간** (옵티마이저 step, 데이터 로딩, 검증 오버헤드 제외한 하한 추정).

## 12. 테스트가 보장하는 것

`tests/test_model.py` (TINY: V=97, ctx 32, L=2, H=4, d=32), 9개:

1. `test_param_count_formula`: tied/untied 모두 실제 파라미터 수 = 8절의 공식.
2. `test_manual_attention_matches_sdpa`: 수동 attention과 SDPA의 로짓이 1e-5 이내로 같다.
3. `test_causal`: 위치 10 이후 토큰을 바꿔도 앞 10개 출력은 불변, 뒤쪽 출력은 변한다.
4. `test_kv_cache_matches_full_forward`: prefill + 토큰 단위 decode가 전체 forward와 같다 (수동/SDPA 둘 다).
5. `test_rope_depends_only_on_relative_position`: 상대 위치가 같으면 내적이 같고 회전이 노름을 보존한다.
6. `test_rmsnorm_and_cross_entropy_match_torch`: `F.rms_norm`, `ignore_index=-1`의 `F.cross_entropy`와 일치.
7. `test_initial_loss_is_near_uniform`: 초기 loss가 `ln 97`의 0.1 이내.
8. `test_overfits_one_sequence`: 한 시퀀스를 150 step SGD(lr 0.5)로 외워 loss < 0.5 (end-to-end 기울기 검증).
9. `test_generate_greedy_matches_argmax`: greedy 생성이 shape `(2, 11)`이고 각 토큰이 전체 forward의 argmax와 같다.

## 14. 실습

1. **마스크 제거**: `Attention.forward`에서 마스크를 모두 허용으로 바꿔(수동 경로 `sdpa=False` 기준) `test_causal`이 실패하는 것을 확인하라. 어느 단언이 먼저 깨지는가? 학습 loss는 왜 비정상적으로 빨리 0에 가까워지는가?
2. **untie**: `tie_embeddings=False`로 파라미터 수를 공식으로 먼저 계산하고(small: 8절 + 4,194,304) 실제와 비교하라. 같은 step 수에서 초기 loss와 학습 곡선이 어떻게 달라지는가?
3. **GQA**: `n_kv_head < n_head`를 추가해 `k`, `v` head를 여러 query head가 공유하게 하라. `qkv` 출력 폭과 KV cache 크기(`2·L·S·d`가 어떻게 바뀌는지)를 식으로 쓰고 `test_kv_cache_matches_full_forward`를 통과시켜라.
4. **KV cache 속도**: 같은 프롬프트로 `generate`를 캐시 있음/없음(매번 `self(ids)` 전체 재계산)으로 비교해 토큰당 시간을 S에 대해 그려 보라. 10절의 `O(S)` 대 `O(S²)`가 보이는가?
5. **RoPE vs 학습된 절대 위치**: RoPE를 `Embedding(ctx_len, d)` 위치 임베딩으로 바꿔 같은 step의 val loss를 비교하라. 학습 길이(512)를 넘는 길이로 평가하면 각각 무슨 일이 생기는가?
